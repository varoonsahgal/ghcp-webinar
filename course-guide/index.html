Chapter 02 · Ground school

Harness, agent, model

Three separate dials that people blur into one word, "Copilot". Keeping them apart explains most surprises.

The three dials

Module 0

The model is the brain. The agent is the role it plays. The harness is the engine that runs the loop, applies permissions and calls tools.

  • Model: a specific model, or Auto, which picks per request and is 10% cheaper.
  • Agent: Ask, Plan, Agent, or a custom agent such as the course's Orchestrator. An agent is a persona plus a tool list plus, optionally, a model and hooks.
  • Harness, chosen with Session Target: Local (VS Code's own loop, used in most labs), Copilot (the Copilot CLI engine), Claude, Codex, and Cloud (runs remotely, returns a PR).

The agent loop

Foundations

A model on its own only writes text. An agent works because the harness offers the model a menu of tools (read, search, edit, execute, start a subagent, and every tool from your MCP servers). When the model replies with a tool request, the harness checks the rules, runs it, and feeds the result back. The loop repeats until the model answers in plain text.

Why the harness matters

Module 2

Hooks, tool names and some settings are harness-specific. A Local hook uses events like PostToolUse and fields like tool_name; the Copilot harness reads the same .github/hooks folder but uses Copilot CLI's camelCase events and payloads. That's why the hook labs pin Session Target → Local.

Analogy

The model is a brilliant contractor who can only talk. The harness is the site office: it hands out the tools, keeps the sign-in sheet and enforces site rules. The agent is the job title on the badge. Move to a different site office and the rules change, even with the same contractor.

The Agents window, and weekly releases

Module 0

The Agents window (Stable since 1.120, May 2026) is built for assigning and reviewing many agent sessions: worktrees, Dev Containers, scheduled automations, a Changes panel and Create PR. VS Code has shipped weekly since 1.111 (March 2026), so screens drift fast. When a menu has moved, search the Command Palette.

Tidbit

Edit mode was deprecated in 1.110 and then removed. Ask, Plan and Agent are themselves just custom agents with different tool lists. If you want a "constrained editor", you write one.

Chapter 03 · Ground school

Tokens & AI Credits

Since June 1, 2026 you pay for what the model reads and writes, not for how many times you press Enter.

Tokens and credits

.19

1 AI credit = $0.01. Each request is metered by input, cached input and output tokens, at the price of the model that handled it.

Analogy

The old premium request was a bus ticket: one fare per ride. AI Credits is a taxi meter: it runs for the whole trip. A 40-step agent loop that rereads the same five files is a long detour.

What drives cost

.19
  • The whole context is re-sent every step. Caching makes repeats cheaper, not free.
  • Tool results pile up. File reads, test logs and big MCP results outweigh what you typed.
  • Every enabled tool costs tokens every turn. An MCP server with 40 tools you never use isn't free.
  • Subagents multiply. Each has its own context and its own bill.
PlanPriceCredits / month
Pro$101,500
Pro+$397,000
Max$10020,000
Business · Enterpriseper seat1,900 · 3,900 per user, pooled

Code completions and Next Edit Suggestions don't use credits. Check the live price list before relying on numbers.

Trap

Long agent loops with a big model add up fast. In the course's worked example, one 30-step session costs about 160 credits on Opus versus about 37 on a lightweight model. Give read-only subagents a cheap model:, and start a fresh chat per task.

Chapter 04 · Part A

The autonomy ladder

Each rung buys speed with tokens and trust. Choosing the lowest rung that gets the job done is the skill.

Autonomy is a dial

Module 0 · .2

Each rung gives the AI more freedom to act without asking you, and needs more guardrails to be safe.

Analogy

Ask is a passenger giving directions. Agent is a learner driver with you beside them, approving each turn onto a main road. Autopilot is letting them drive alone. Hooks, checkpoints and server-side guardrails are the brakes you fit first.

#RungWhat it doesUse it when
1AskRead-only tools. One bounded answer.Explaining, exploring, one-shot answers.
2PlanResearches, asks clarifying questions, writes a plan.The change is risky or fuzzy.
3AgentEdits, runs commands, calls MCP tools, fixes its own mistakes. You approve tools.Multi-step work you can verify.
4AutopilotAgent with approvals switched off.Hooks and checkpoints have your back.
5Agent teamA coordinator plus least-privilege specialists, some in parallel.Big tasks with separable parts.
6Cloud agentRuns on GitHub's machines, returns a PR.Well-specified chores you'll review anyway.

Is Agent overkill?

Discussion

An Agent turn can run 10 to 40 tool calls. Under token billing, Ask with good context is often genuinely cheaper. Reach for Agent when the work needs doing, not just knowing.

More autonomy is not always better.

Tidbit

A 2025 METR study measured 16 experienced open-source developers as 19% slower on real tasks with AI tools, while they believed they'd been about 20% faster. Measure, don't assume.

Chapter 05 · Part A

Context & context rot

The model has no memory between calls. Everything it "knows" is whatever the harness packed into this one request, and more isn't better.

The context window

.12 · 2.04

The context is everything the model sees on a turn. The window is the most it can hold, in tokens.

A fresh chat doesn't know your other chat. A subagent doesn't know its parent's history. An MCP server's tool descriptions are in every request; its results pile up as the session runs. If something must survive, write it somewhere that gets loaded: instructions, a skill, a plan file.

Analogy

The context window is a desk, not a filing cabinet. A bigger desk lets you spread out more papers, but pile on enough old drafts and stack traces and you start working from the wrong page.

Context rot

Module 2

The measurable drop in quality as input grows, long before the window is full.

  • Lost in the middle. Early instructions in a long session end up in the middle, where models use them least.
  • Distractors. An old stack trace or the previous version of a file actively misleads.
  • Symptoms: forgets a rule it followed an hour ago, reintroduces a fixed bug, rereads files, invents names.

The hygiene toolkit

Chapter 06 · Part A

Plan, checkpoints, Git

Think before you build, and know exactly which undo button covers what.

The Plan agent

1.94

Researches with read-only tools, asks clarifying questions, and writes a reviewable plan before any code changes.

Run /plan …. In the Local harness the plan lives in session memory (/memories/session/plan.md); then choose Start Implementation or Open in Editor to tweak it first. A plan file is externalized memory: it survives compaction and new sessions.

Cheap trick

Plan with a strong reasoning model, implement with a cheaper one. Set chat.planAgent.defaultModel, or choose Approve Plan Only and switch models.

Checkpoints

Every lab

Snapshots of workspace files and chat at each request. Hover a request → Restore Checkpoint.

Analogy

A climber clips into a bolt every few metres, so a fall only drops them to the last clip. But a clip can't catch a rock already knocked onto someone below. Checkpoints don't undo terminal commands, database writes or MCP tool calls.

ActionCheckpointGit
Files the agent editedRestoresIf committed
Terminal commands, installsNoTracked files only
MCP tool calls (DB writes, API calls)NoNo
Pushed commitsNoRevert, visibly

Nothing in the editor undoes a DELETE on prod.

Chapter 07 · Part B

Where guidance lives

Rules go in instructions. Tasks go in prompt files. Roles go in custom agents. Know-how goes in skills. Must-always-happen goes in hooks.

Instructions are context, not enforcement

1.92

Repo instructions travel with every request: Ask, Plan, Agent, custom agents and subagents. They are not used for inline ghost-text suggestions.

Prove they were used: expand References under an answer, or find the text in the Chat Debug view's system prompt. A harmless "canary" rule (end every response with "📏 repo rules applied") makes it visible.

Trap

applyTo belongs in *.instructions.md. In a prompt file it does nothing. And a copilot-instructions.md in the repo root instead of .github/ is silently ignored.

AGENTS.md: a README for agents

2.06

One short file of project-wide rules that every agent tool reads. Custom agents define roles; AGENTS.md defines shared standards. Nested files per folder are experimental in VS Code (chat.useNestedAgentsMdFiles).

Trap

Everything that applies is combined into one prompt, and a custom agent's own body claims precedence. If the Designer's file says "use inline styles" and AGENTS.md says "no inline styles", don't rely on precedence. Remove the contradiction.

Chapter 08 · Part B

Skills

On-demand know-how, with scripts and resources, that costs almost nothing until it's needed.

Agent Skills

2.07 – 2.10

A folder with a SKILL.md and optional scripts, templates and references. Only its name and description are in context until a task matches.

Analogy

A library gives you a card per book, not every book on your desk. You fetch the book whose card matches, and only open the appendix if the chapter sends you there. A skill's description is its catalog card.

The rules that bite

2.08 · 2.10
  • The name must match the folder and be lowercase with hyphens. A bad name fails silently; it's the number one "my skill doesn't show up" cause.
  • The description is the trigger. Say what it does and "Use when…", in the words users type.
  • Scripts must print. An agent can only use what a script writes to the terminal.
  • Vite projects are ES modules. A .js script with require() crashes there. Use import, or name it .cjs.
  • disable-model-invocation: true makes a skill run only via /name; user-invocable: false hides it from the menu.
Trap

Community skills run code on your machine. Read the scripts before you add one, exactly as you would a dependency.

Chapter 09 · Part B

Hooks

Instructions are requests. Hooks are code that runs every time, at fixed points, and can say no.

Hooks

2.12

Commands the harness runs at lifecycle events. They get the event as JSON on stdin and can log it, add context, or block.

Analogy

"Please pay your fare" is an instruction. A turnstile is a hook. It doesn't care how persuasive you are.

The self-healing build loop

2.12

A PostToolUse hook runs npm run build after every file edit. If it fails, the hook returns a structured block with the compiler output, and the agent fixes its own mistake.

{ "hooks": { "PostToolUse": [
  { "type": "command", "command": "node .github/hooks/scripts/build-validator.cjs", "timeout": 120 }
] } }
// on failure, print and exit 0:
{ "decision": "block",
  "reason": "The project no longer builds. Fix the errors below.",
  "hookSpecificOutput": { "hookEventName": "PostToolUse",
    "additionalContext": "npm run build failed: Could not resolve ./BatteryWidget …" } }
Trap

There's no tool filter in the config: hooks fire for every tool call. Your script checks tool_name itself (replace_string_in_file, create_file, apply_patch…). Test it by piping fake events: echo '{"tool_name":"create_file"}' | node …

Exit codes and events

Local harness
ExitMeaning
0Success. Stdout is parsed as JSON.
2Blocking error. Stderr goes to the model.
otherWarning only; processing continues.

Events: SessionStart · UserPromptSubmit · PreToolUse · PostToolUse · PreCompact · SubagentStart · SubagentStop · Stop. A Stop hook can say "not done yet" (guard it with stop_hook_active, or it loops and bills).

Make guardrails guard themselves

A PreToolUse hook that denies edits to .github/hooks/ means a confused agent can't switch off the hook that's blocking it. That's the difference between a rule and a lock.

The frontmatter that matters

2.02
---
name: Orchestrator
description: Breaks work into phases and delegates. Never writes code.
model: ['Claude Sonnet 5.5 (copilot)', 'GPT-5.6 Terra (copilot)']  # list = fallbacks
tools: ['read/readFile', 'agent', 'vscode/memory']                 # no edit!

---
  • user-invocable: false hides a specialist from the picker; it's subagent-only.
  • disable-model-invocation: true is the reverse: humans can pick it, agents can't call it. Good for an independent reviewer.
  • Nesting is off by default (chat.subagents.allowInvocationsFromSubagents, max depth 5).
  • No setting is needed any more to use custom agents as subagents.
Trap

A subagent doesn't inherit your conversation. Write its task like a ticket: goal, what it may touch, what to return. The requirement you typed three messages ago isn't there unless the coordinator passes it on.

Least privilege

A hotel key card opens your room, not every room. A Planner without edit can't edit, however confused it gets. Saltzer and Schroeder wrote the principle down in 1975; it fits agents perfectly.

Chapter 11 · Part C

Prove what happened

"It worked" is a claim. Logs are the evidence.

Two X-rays

2.04
  • Chat Debug view (/debug): the exact system prompt, context, tools and response for each request. Is my instruction there? What did the model see about my MCP tool?
  • Agent Debug Logs: a timeline of model calls, tool calls, subagents and discovery events, plus a flow chart and a token Summary.
Empty panel?

Logs aren't retroactive. Turn on github.copilot.chat.agentDebugLog.fileLogging.enabled and reload before the run.

/troubleshoot Which subagents ran, which model did each use, and which one used the most tokens?

Local vs cloud agents

The same .agent.md files can drive an agent on your laptop or in GitHub's cloud. Same format, very different execution.

Side by side

2.13

Runs onYour machine or a Dev ContainerAn ephemeral GitHub Actions sandbox

"Copilot coding agent" is now called Copilot cloud agent in GitHub's docs.

What makes a good cloud task

2.14

Bounded, testable, PR-shaped, reviewable.

The incident lab delegates a retry bug: the service hammers a rate-limited provider, ignoring Retry-After. The issue states symptoms, suspected cause, acceptance criteria and how to validate (npm test). Issue quality decides PR quality.

Review like a lead engineer

Check the diff is focused, tests would fail on the old code, nothing unrelated changed, and timing tests aren't flaky. Retry-After as an HTTP-date has one-second precision, so a 1.5-second threshold fails at random.

Delegate a bounded task, then review the PR like it's yours.

Chapter 13 · Part D · MCP

What MCP is

The Model Context Protocol is an open standard for connecting AI applications to tools and data. One plug shape, many devices.

USB-C for AI

3.01 · 3.02

Before MCP, every AI app needed a custom integration for every tool. With MCP, each side implements the protocol once.

Analogy

Before USB, every printer, mouse and camera had its own connector and driver. USB-C means one port takes them all. Three AI apps and ten tools used to be 30 integrations; with MCP it's 13 implementations.

Tidbit

Anthropic introduced MCP in November 2024 and donated it to the Linux Foundation's Agentic AI Foundation in December 2025, so no single vendor controls it.

Host, client, server

3.02
RoleWhoDoes
HostVS Code + CopilotRuns the model, manages connections, shows approvals
ClientOne per server, inside the hostSpeaks MCP to exactly one server
ServerYour code or someone else'sExposes capabilities and does the real work

Copilot thinks. Servers act. Servers enforce.

Three primitives, three controllers

3.02 · 4.01
PrimitiveControlled byExample
ToolsThe model decides to call themrun_sql_query, create_issue
ResourcesThe app or user attaches themcatalog://schema
PromptsThe user runs them/service-catalog.incident-brief

A server can also ask the user a question mid-call (elicitation, Chapter 19).

MCP is not RAG

3.02

RAG retrieves documents into the prompt. MCP calls live systems and returns structured results, and can take actions. They combine: a docs server like Context7 is retrieval exposed over MCP, which is why the course's Coder agent checks it before writing code.

Chapter 14 · Part D · MCP

One protocol, many transports

JSON-RPC is the language. The transport is the delivery truck. Change the truck and the conversation stays the same.

Protocol vs transport

3.03 · 3.08

MCP messages are always JSON-RPC 2.0. They travel over stdio (a local process) or Streamable HTTP (a web endpoint).

Analogy

The Rosetta Stone carries one decree in three scripts. The meaning didn't change with the script, which is exactly why it could be decoded. In Lab 3.08 you swap HTTP for stdio and the same tools behave identically.

The four message shapes

3.03
request       {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"run_sql_query","arguments":{…}}}
result        {"jsonrpc":"2.0","id":3,"result":{"content":[{"type":"text","text":"[…]"}]}}
error         {"jsonrpc":"2.0","id":3,"error":{"code":-32602,"message":"Unknown tool"}}
notification  {"jsonrpc":"2.0","method":"notifications/initialized"}      ← no id, no reply (HTTP 202)
Why REST isn't MCP

Lab 3.05's first server has GET /mcp and POST /mcp/call. It looks reasonable, but Copilot sends JSON-RPC to POST /mcp starting with initialize, and gets a 404 page back. "Waiting for server to respond to initialize" in the Output log is the clue.

stdio vs Streamable HTTP

3.03
stdioStreamable HTTP

Tidbit

The original 2024 "HTTP+SSE" transport is deprecated. In mcp.json, "type": "http" means Streamable HTTP.

Chapter 15 · Part D · MCP

Wiring servers into VS Code

Copilot doesn't scan anything. VS Code reads config, checks trust, starts or connects, lists tools, and hands them to the model.

The config file

3.00 · 3.04
// .vscode/mcp.json
{
  "inputs": [{ "type": "promptString", "id": "catalog-key", "description": "API key", "password": true }],
  "servers": {
    "service-db": { "type": "stdio", "command": "node",
                    "args": ["${workspaceFolder}/mcp-server/stdio-server.js"] },
    "catalog":    { "type": "http", "url": "http://localhost:4000/mcp",
                    "headers": { "Authorization": "Bearer ${input:catalog-key}" } }
  }
}
servers vs mcpServers

VS Code's own .vscode/mcp.json uses servers. The portable root .mcp.json, the Inspector, Claude and Copilot CLI use mcpServers. Mixing them up is the top "my server doesn't appear" bug.

Trust, startup, caching

3.04
  • Trust: workspace servers inherit Workspace Trust. Others show a trust dialog the first time.
  • HTTP servers: the Restart lens only reconnects. It doesn't run node for you.
  • Stale tools: VS Code caches tools/list. After changing tools, restart the server or run MCP: Reset Cached Tools.
  • Install from the gallery: search @mcp in the Extensions view.
  • Debug: MCP: List Servers → Show Output shows the handshake and errors.
Chapter 16 · Part D · MCP

How the model picks a tool

The model never makes a network call. It reads tool descriptions, asks for a call, and the host places it.

Model chooses, host connects

3.06

The model emits "call run_sql_query with this SQL". VS Code asks your permission, sends tools/call, and returns the result.

Analogy

A caller tells the operator who they want. The operator decides whether to connect, plugs the cord into the right jack and stays on the line. The caller never touches the wiring. The model is the caller; VS Code is the operator.

Descriptions are prompts

3.06

Change a tool's description to "Utility function" and Copilot stops calling it. Write "Query the service inventory (table services: name, owner, environment, criticality). Use for questions about which services exist…" and it calls it immediately, with better SQL.

  • The model chooses individual tools, not servers. A server is a toolbox.
  • Parameter descriptions matter too: valid values in the description mean fewer probing queries.
  • The Chat Debug view shows exactly what the model saw about your tool.

Your tool description is prompt engineering.

How it discovers a schema

3.07

Nobody told Copilot the table names. Because the tool accepts raw SQL, it probes: SELECT name FROM sqlite_master, then PRAGMA table_info(services). That's clever, and it's also exactly why raw SQL is dangerous: the same freedom that discovers can also DROP TABLE.

Chapter 17 · Part D · MCP

The security boundary

MCP lets a client call tools. It does not make those tools safe. Your server is the gate.

Tool calls are untrusted input

3.11

Treat every tools/call like a form post from the internet. A misunderstanding, a careless prompt or injected text all arrive as perfectly valid JSON.

Analogy

The castle doesn't rely on visitors promising to behave. The gate decides who and what gets through, whatever the visitor says. In Lab 3.11, "Delete all prod services" deletes prod until the server's gate closes.

The defensive patterns

3.11 · 3.12
PatternIn the course
Capability checks over string checksstmt.reader asks SQLite whether a statement only reads. startsWith("SELECT") wrongly blocks WITH … SELECT and is easy to fool.
Defense in depthAlso open the database { readonly: true }, so a bug in your check can't hurt you.
Remove the capabilityReplace run_sql_query(query) with three narrow tools that take enums and run fixed, parameterized queries.
Dry-run by defaultdelete_services_by_environment previews unless told otherwise.
Re-validateA schema enum guides well-behaved clients; the server still checks.
AuditLog every call with its outcome.
The confirm-token trap

Lab 3.11's prod delete needs confirmToken: "DELETE_PROD", but the token is written in the tool's description, so the model can supply it itself. That's a speed bump against accidents, not human confirmation. Real confirmation asks the human: elicitation, Chapter 19.

Chapter 18 · Part D · MCP

Designing great tools

A tool definition is an API contract and a prompt. Models read every word; programs rely on every field.

Anatomy of a tool (SDK v2)

4.02
server.registerTool("get_service_health", {
  title: "Get service health",                                   // what humans see
  description: "Current health snapshot for one service: status, " +
               "error rate and p95 latency.",                    // what + when
  inputSchema: z.object({ service: z.string().regex(/^[a-z0-9-]+$/) }),
  outputSchema: Health,                                          // typed results
  annotations: { readOnlyHint: true, idempotentHint: true },     // behavior hints
}, async ({ service }) => {
  const snapshot = await lookup(service);
  return { content: [{ type: "text", text: JSON.stringify(snapshot) }],
           structuredContent: snapshot };                        // both!
});
  • One job per tool, named verb_noun.
  • Tight inputs: enums, ranges, patterns. Invalid input never reaches your handler.
  • Output schema: the SDK refuses to send results that break your own contract ("Output validation error").
  • Annotations (readOnlyHint, destructiveHint…) are hints for UX and approvals. Clients mustn't trust them from unknown servers.
  • Bound your output: a 100,000-line log eats context and credits. Cap it and say so in the description.

Two kinds of errors

4.02
KindExampleHowWho reads it
Tool execution errorBad business input, policy block, failed APIisError: true result (or throw)The model, which can self-correct
Protocol errorUnknown tool, malformed requestJSON-RPC errorThe client
Trap

A thrown error's message goes straight to the model, and into transcripts and logs. A raw database error can leak SQL, paths or hostnames. Catch it, sanitize it, return something helpful.

Chapter 19 · Part D · MCP

Resources, prompts, elicitation

Tools aren't the only primitive. Give users context they can attach, templates they can run, and a way for your server to ask them a question.

Resources and prompts

4.01
  • Resources: catalog://schema or a template like catalog://services/{name}. In VS Code, Add Context → MCP Resources. The answer uses the record without a tool call.
  • Prompts: /service-catalog.incident-brief asks for service and symptom, then sends a ready-made task. Arguments can autocomplete (completable()).
  • Server instructions: one paragraph added to the system prompt of every client. "Prefer list_services over raw SQL. Never guess owners."

Elicitation: the server asks the human

4.03

Mid-call, the server asks the user a structured question (a small form), and continues with the answer.

decommission_service asks "Decommission analytics-worker (dev, low criticality, owned by Data Team)?" with a confirm box and a reason. Decline, and nothing is deleted.

The bug we hit building the lab

In the modern branch, if the server only checks "do I have an accepted answer?", a decline looks the same as "haven't asked yet", so it asks again forever (the client gives up after 10 rounds). Check whether any answer arrived first.

Two different gates

VS Code's tool approval asks "may the agent call this tool?". Elicitation asks "do you, the human, confirm this specific action, and why?". The second comes from the server, so a client's auto-approve setting can't skip it. And never ask for secrets in a form: use URL-mode elicitation or proper auth.

Chapter 20 · Part D · MCP

Remote servers & sandboxing

Once a server listens on a port, it's a web service. Once it runs locally, it runs as you.

A remote server, minimum viable safety

4.04
const app = createMcpExpressApp({ host: "127.0.0.1" });   // Host-header allow-list on
app.all("/mcp", requireApiKey,                            // bearer token, constant-time compare
  (req, res) => mcp(req, res, req.body));                 // createMcpHandler: stateless, both eras
app.listen(4000, "127.0.0.1");                            // loopback only
  • DNS rebinding: a malicious web page makes your browser call 127.0.0.1 under its own hostname. Checking Host and Origin stops it (wrong Host → 403, even with the token).
  • Secrets: ${input:catalog-key} with "password": true keeps the key out of the repo.
  • Next step: OAuth 2.1 so the server knows who, not just "someone with the key".

Sandboxing local servers

4.04 · macOS/Linux
"sandbox": {
  "filesystem": { "allowWrite": ["${workspaceFolder}/data"], "denyRead": ["~/.ssh", "~/.aws"] },
  "network":    { "allowedDomains": ["registry.npmjs.org"] }
},
"servers": { "service-catalog": { "type": "stdio", "command": "node",
  "args": ["${workspaceFolder}/mcp-server/catalog-server.js"], "sandboxEnabled": true } }

Tool calls to sandboxed servers are auto-approved, because the sandbox is the safety net. Admins can require it.

Analogy

A sandboxed server is a contractor working in one room with the other doors locked. They can do the job; they can't wander into the study.

Inspector & testing

"It worked when I tried it in chat" isn't a test. Drive your server directly, without a model.

MCP Inspector

3.09 · 3.10

The official debugging client: a web UI, a CLI and a TUI in one package. It shows the handshake, tool schemas, raw requests and responses, HTTP status codes and stderr.

npx @modelcontextprotocol/inspector                        # web UI (opens a URL with a session token)
npx @modelcontextprotocol/inspector --cli node server.js --method tools/list
npx @modelcontextprotocol/inspector --cli http://localhost:3333/mcp --transport http \
    --protocol-era legacy --method tools/call --tool-name run_sql_query --tool-arg "query=SELECT 1"

Needs Node 22.19+. If Copilot is the black box, the Inspector is the glass box.

Lab 3.10 hides three protocol bugs in one server. Each shows a different symptom:

SymptomCause

Three layers of confidence

4.05
  • Unit tests with node:test and the SDK's client: list tools, call them, read resources, assert.
  • Contract gate: inspector --cli … --method tools/list --strict exits 6 on non-portable schemas (a z.tuple does it).
  • Era check: run with --protocol-era legacy and modern.
Analogy

Carmakers don't find out about crashes from customers. They crash cars on purpose, with dummies full of sensors. Your test suite is the dummy.

Chapter 22 · Part D · MCP

MCP in 2026

The July 2026 spec made MCP stateless. Here's what changed, and what it means for servers you write today.

Then vs now

4.00
Legacy (≤ 2025-11-25)Modern (2026-07-28)
Openinginitialize → initializedNone; optional server/discover
VersionNegotiated onceOn every request (_meta + header)
SessionsMcp-Session-IdNone; state lives in explicit handles
Asking the userServer-initiated requestinput_required result + retry (MRTR)
Optional featuresIn coreExtensions: Apps, Tasks, …
DeprecatedSampling, roots, logging, HTTP+SSE (working for at least 12 more months)
Where VS Code is

We checked VS Code 1.140: its built-in MCP client still opens with initialize (2025-11-25). So servers must speak the legacy era to work in VS Code today, ideally dual-era so modern clients work too.

SDK v2 entry points

4.00
CodeEras served
server.connect(new StdioServerTransport())Legacy only (fine for VS Code)
serveStdio(() => buildServer())Both, over stdio
createMcpHandler(() => buildServer())Both, over HTTP, stateless

Packages moved from @modelcontextprotocol/sdk (v1) to @modelcontextprotocol/server and /client (v2), with z.object(…) schemas from zod/v4. A model trained before mid-2026 will happily write v1 code, which is exactly the case for a docs MCP server.

Watch it happen

Point the Inspector at Lab 3.05's hand-written server in auto mode. Your terminal shows server/discover → 404 → initialize: a modern client politely falling back to an older server.
